# M1 / N / L / M2 / S — 动机前审、近邻查重、逻辑与动机复审、科学故事

## 不可颠倒的优先级

允许先产生 `IDEA_SEED`，插件主动搜索现有/衍生数据完成 D0/G0；先执行 M1 初审真实问题，再冻结并近邻查重 N，执行 L 机制逻辑，再做 M2 动机复审，最后才进入 S 故事线。必要时回退任一环节。G7 和 G8 不能取代 G0、机制级查重、科学证伪。故事不是编故事：没有观察、文献、数学命题或可复现证据的“重要性”“第一次”“显著提升”一律不得写成事实。故事好听但问题不成立 -> STOP/REFINE。

## M1 初审与 M2 复审：动机需经过两次不同目的的检查

研究问题的 6 个不可相互抵消的检验项：

1. **现实中的痛点（Evidence）**：谁/哪种任务/哪种条件下失败？最好有原论文表格、消融、失败图、重复诊断、反例或可核查的实际数据；若还没有，只标 HYPOTHESIS。
2. **实际重要性（Stakes）**：失败的代价、频率、泛化/安全/可信/效率含义是什么？不强求商业价值，但要说清楚其科学价值。
3. **真正根因（Cause）**：此前方法依赖什么隐含假设？失败原因的两种竞争解释是什么？现有证据能否把它们区分？
4. **已有路线为何不够（Necessity）**：给最强已有方法和最简单 baseline 最大解释空间；它们在哪个明确条件下失败？
5. **现在为什么值得做（Timeliness）**：新数据、协议、理论矛盾或方法进展是否带来可验证的机会？如无充分证据，可写“目前意义待证”，严禁捏造热度。
6. **独有可证伪预测（Distinctive prediction）**：新假设能预测哪种可观测差异？反证信号是什么？没有判别性结果则不能升级成正式 Idea。

逐项输出 `SUPPORTED / PLAUSIBLE_UNTESTED / CONTRADICTED / UNKNOWN` + 引文/可定位证据 + 当前最有力反驳。论文主张、作者反驳、客观事实分列；对理论/系统/材料类研究按各领域证据和产出形态调整。

仅当最关键的失败/问题证据可核查、假设可证伪、差异性可识别时，通过 `MOTIVATION_EVIDENCE_PRESENT`（结构门，不是真实科学质量认证）；证据不足则 `MOTIVATION_UNVERIFIED`；已被反例证伪则 `MOTIVATION_REJECTED`。不为了凑 2–4 个想法继续生成。

## S 故事线不是“美化”，而是 9 环节论证链

读者阅读顺序：
`真实场景/科学悖论 → 现有最强路线与成功边界 → 核心失败案例 → 根因和被违反的假设 → 可证伪科学命题 → 不可替代的最小新机制/理论/评测 → 与最危险近邻的实质差异 → 独特预测和决定性实验 → 贡献、适用边界和负面结果`。

要求输出三种形式，内容完全一致，不能为叙事改变技术事实：
- **30 秒陈述**：3–5 句话回答为什么问题重要、以前为何不够、我们有什么新论断、怎样验证。
- **Introduction 逻辑提纲**：痛点、已有做法、不可解释的失败、核心 insight、解决方案、验证设计、贡献。
- **审稿人证据图**：每个大主张对应哪个已有结果/计划中的关键实验、何时补齐，区分 `SUPPORTED/PLANNED/UNKNOWN`。

必须分别检验 `problem worth solving`、`solution necessary`、`novel delta`、`proof convincing`，不能靠文笔补齐任何一项。

## 三次不同目标的攻击，而不是重复润色

- **Round M — 动机质疑**（问题审稿人）："这个问题真的普遍/重要吗？有没有更简单解释？" 查找反例、排除虚假的普遍性描述。若论据缺失，回退 E0，不继续包装。
- **Round N — 必要性与创新质疑**（最危险近邻审稿人）："强 baseline 已经解决了吗？你是不是旧模块的新名字？" 需具体 mechanism delta 与区分性预测，撞车则 PIVOT。
- **Round R — 冷读说服力压力测试**（独立/隔离审稿人）：隐藏作者辩护先读 30 秒陈述/图 1 计划/Introduction 提纲，写最有杀伤力的拒稿理由，然后基于证据修复，不用修辞掩盖。

每次记录 `round, attack, strongest_counterargument, response, new_evidence_or_mechanism_delta, unresolved_objections, decision`；只有引入**新的可靠证据、收紧假设或机制实质修改**才认作有效修订。重复换标题、换术语、堆形容词不算一轮。最多 3 轮候选机制迭代，无法解决核心拒稿点输出 `REFINE/PIVOT/STOP/UNVERIFIED`。不要求实际调用 3 个独立模型；若仅同模型模拟角色必须标 `ROLE_SIMULATED`。

## 一票否决与结果类型

- `M1/M2`: 只有热词/新模块，没有可核查问题与重要性；根因证据薄弱；强简单对手已解决；可证伪预测缺失 -> 不晋级正式 Idea。
- `S`: 故事逻辑跳跃、核心 Claim 无实验、强近邻绕开不讲、用已知负面结果换取好看叙事 -> 不交付“可投稿完整故事”。
- 审核结论：`MOTIVATION_EVIDENCE_PRESENT / MOTIVATION_RECHECK_PRESENT / LOGIC_ARGUMENT_PRESENT` 只表示审查材料的格式满足要求；`STORY_STRUCTURE_READY_FOR_REVIEW / STORY_REVISE / STORY_UNVERIFIED` 也不是实际投稿成果认证。**这只是论证结构/证据存在性的检查，绝不等于真实审稿人被说服、论文可录用。**
- 保留负面判断和 failed ideas；允许最终零 Idea。

## 和实验的双向反馈

经过 pilot 后必须回填故事链：若 E0 无目标现象，立即撤回痛点强断言；若简单基线足够好，撤回方法必要性；若主要提升来自计算预算/更大 backbone，不得归因于新机制；若只在窄场景有效，改写适用边界而非夸大普遍性。
