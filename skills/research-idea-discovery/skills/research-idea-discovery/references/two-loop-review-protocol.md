# Two-Loop Research Review — CCF-A 研究 Idea 审计流程（领域用户自选）

## v3.3 前置动机 M0（覆盖下文旧版顺序）

在两个旧循环之前插入 Problem Scout → M0。只有可定位问题证据、科学重要性、替代解释和可证伪的最小检查满足准入标准才进入旧 Loop A 的 IDEA_SEED。弱动机禁止启动 D0/G0、详细近邻查新与方法设计；可做无新方法的针对性复现检查。详见 `motivation-first-gate.md`。旧 Loop A 的 M1、M2 不删除：M1 在数据/资源核实后强化动机；M2 在近邻分析后再次收缩命题。

## 总原则

**不是**先写故事再找科学依据。用户只负责指定研究范围及确实不可回避的资源约束；插件自己从论文发现 Idea，并查公开/授权现有或可轻量衍生的数据集、可复现基线、明确评价协议。`IDEA_SEED` 允许未经数据确认；**不允许未通过 D0/G0 的 Seed 成为正式候选**。

## Loop A：选题价值（idea selection）

1. `IDEA_SEED`：提出可证伪的科学命题，标出必要数据字段、最小反证实验。
2. `DATA_SEARCH → D0 → G0`：插件检索可访问的现有/父数据、标签、代码、许可、算力和 E0；无路径则收窄/淘汰。
3. `M1 MOTIVATION_INITIAL`（在正式新颖性审计**之前**）：基于已观察到的问题证据回答“为何这个问题值得做”。需任务/失败、影响、隐含假设、至少两个替代解释、强基线局限、可反驳预测。此时仅声称**初步**动机，不能宣称首次。
4. `FREEZE → SCOOP (N)`：锁定 Idea ID/revision，检索 3–7 篇真实高威胁近邻，尽量核查全文、附录、代码。对研究问题、假设、决策粒度、运算、监督、区别性预测六轴比较；查重未完标 `NOVELTY_UNVERIFIED`。不得把“未找到论文”认作原创。
5. `MECHANISM_LOGIC (L)`：根因→机制修改→独有可观察预测→最简竞争方法→消融/反证。至少给出机制必要性理由、一个等价性攻击和对应实验、控制变量与失败边界。若简单 rival 同样解决问题，撤销机制必要性。
6. `MOTIVATION_RECHECK (M2)`：**重新检查同一研究问题**，具体写明原动机、近邻论文已覆盖哪些论点、剩下什么真正重要的缺口、贡献边界与独特预测是否需要改写，依然可被证伪。不能只换名字或复制 M1。核查失败回 `EXPLAIN/DIVERGE` 或停止。

`Loop A` 的正式候选应满足 D0、G0、M1、N、L、M2 均有可靠证据；通过格式门仅表示资料准备好供科研判断，不表示绝对新颖。

## Loop B：论文论证（paper argument）

1. 用 Loop A 幸存的候选编制 `主科学假设 → 最小机制 → killer experiment`：先写 E0 观察、E1 探针、E2 简单 rival、E3 核心模块、E4 外推/成本和不可回避的失败信号。
2. `NARRATIVE (S)`：把痛点、近邻边界、根因、机制、独特可观测预测、对照实验和适用范围组成紧密论证链；分别提供 30 秒 pitch、Introduction 骨架及 Claim→Evidence，严格标 `OBSERVED/PLANNED/UNKNOWN`。漂亮措辞不能填补技术证据。
3. `REVIEW`：至少三次不同的反对：M 动机是否重要，N 新机制是否必要且与近邻不同，R 冷读全文概要是否自然且可理解。缺陷要具体指出证据或实验缺口，不能用多位模拟角色假装独立多模型。
4. `PILOT`：仅在用户允许且工具和资源真实存在时运行。若未运行，写 `PLANNED` 并不宣称论文已准备投稿。Pilot 结果与强基线、随机种子、开销和失败案例反向更新 M1/N/L/M2/S；E0 无目标现象就撤回动机，E2 强 rival 无劣势就撤回必要性，避免事后选择性挑数据。
5. `UPDATE → REVISE / PIVOT / STOP`：允许基于新证据回退到恰当节点，不机械规定每轮必须升级；无法修复时允许 0 个正式 Idea。审稿打动程度是**基于科学证据和论证质量的判断**，绝不许预测必然被录用。

## 对齐五个独立判断

| 判断 | 用户真正要知道 | 否决证据 |
|---|---|---|
| G0 可行性 | 数据和资源支持实证检验吗？ | 必要数据/授权/评价/基线无法获得 |
| M1/M2 动机 | 问题真实重要，且经近邻比较仍值得做吗？ | 主要痛点不存在，或已有方法完全解决 |
| N 新颖性 | 独有假设/机制/预测相对强近邻确有变化吗？ | 等价算法或同一贡献已发表 |
| L 逻辑与必要性 | 方法确实针对根因，简单 rival 不够吗？ | 机制与根因无关，消融不能证明贡献 |
| S 科学故事 | 是否形成审稿人可以跟踪的证据链？ | 用修辞掩盖逻辑跳跃，主结论没有决定性验证 |

## 证据、版本和门槛

- N/L/M2 记录同一 `idea_id + revision`；修改核心科学命题/机制、切换主要数据时，先前结论失效。
- G0/M1/N/L/M2/S 的失败不可被“创新分数”“故事分数”平均抵消。
- 对于理论论文没有实验数据集的情形，应在用户明确采用理论目标时按数学证明/反例适配；但默认用户资源约束下优先现成或现有数据衍生路线。
- 软件结构门只验证字段/状态完整性，不能替代真实文献阅读和审稿人判断。

## 跨循环证据补给：Deep Research 研究回流

当 Loop A 没有可靠候选，或 Loop B 发现关键文献/数据未知，允许暂停当前研究链并输出定制的 Deep Research 调研任务。保留失败候选与高风险近邻，不制造第三层无穷迭代。外部报告只更新可核实的 evidence ledger，再返回 Loop A 或 B 的受影响节点。不得跳过文献全文/官方数据确认，不能把研究报告的断言当作科学结果。详见 `deep-research-handoff.md`。

## v2.7 必需的执行检查与结果回流

- D0 初步字段卡不能等同实际读取；可用时核查 local small sample，签入样本 SHA256、必需字段、官方来源和许可待审状态。缺乏实际样本时明确 `ACCESS_NOT_EXECUTED`。
- REVIEW 形成已记录且无未解决关键问题的决策后才能转到 PILOT。
- PILOT 若尚未运行，只允许 `PILOT_PLANNED`；若真实运行成功，必须有运行日志与基线对照指标；如失败，保存负面证据。
- 实验显示 simple baseline 等效或更优时，必须重新审查 L/M2/S，不准维持原主张。
- 执行状态是由真实宿主提供的证据决定的；ChatGPT Skills-only 不会自行执行附带 CLI。
