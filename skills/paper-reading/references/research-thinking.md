# 科研思维培养：按需调用的教学规范（v0.7.0）

> 本文件是「论文带读」Skill 的按需教学参考，不是独立的 Idea 生成器。核心思想借鉴 Research-Starter-Kit 所强调的 Topic → Problem → Idea → Concrete Work 和批判性阅读；具体设计由本插件独立实现。用户只需上传一次论文 PDF，不能把研究推测说成论文事实。

## 共同原则：理解是基础，问题是中心，证据是门槛

1. 先帮助读者**准确复述作者**：问题、失败前提、方法、数据、效果；再引导读者提出自己的判断。不能让「批判」变成脱离原文的苛责，也不能用未经证实的 Idea 抢占论文理解。
2. 将「作者主张」与「已观察到的证据」分开；额外标注【合理推测】【待验证研究假设】和【玩具示例】。最重要的判断附论文真实图表号、公式号、页码/章节或检查过的代码位置。
3. Problem-driven 默认优先：找真实且必要的问题 → 探索问题机制 → 判断简单基线能否解决 → 才考虑新方法；Method-driven 迁移也允许，但必须证明被解决问题的必要性和新工具的不可替代价值。
4. 不机械依照「阅读40%、思考60%」计时；不宣称每篇论文都值得提出新方向。允许产出「没有足够证据形成新问题」「建议先补文献或复现实验」。不承诺 CVPR Best Paper 级创新或投稿结果。
5. 不强制学生每轮作答。交互由学生选择「我先回答」或「直接讲你的判断」；一轮**一个有区分力的问题**，学生回答后判断是否切中问题、遗漏关键假设、如何做证据核查，再问是否继续。
6. 不把论文作者的 Future Work 当作未解决且没人做过的新方向；研究新颖性、近期相关文献与已公开代码须独立检索核验。真实领域不足的判断必须和当前论文的结果区分。

## 泛读后科研思考：第三站结束后，读者点击选择进入

**目标**：不借助复杂公式，能独立判断「这是不是一个真实、值得解决的问题；假如没有看作者的方法我会如何做」。不是批量生成 Idea，不计入第三站必讲原图门禁；第三站正式完成后才提供可选入口。

引导顺序：

1. **复述 Problem**：先说用户已掌握的研究问题、现实场景和作者声称的失败模式，不重述七站总结；问读者「这个困难在什么条件下真的出现？哪些条件下并不构成问题？」
2. **自选解法**：先让用户提出一个最低成本方案（最简单基线/不用新模块），再对照作者的核心假设。用户不想回答时提供两个不同思路，说明其条件而不凭空判定优劣。
3. **挑战假设**：选一条真正关键的作者假设，构造一个具体替代条件，例如改变测试样本组成、模态缺失、样本相关性或数据规模；区分原文已经测试和尚未报告。
4. **留下问题种子而非强行立项**：输出**一个**与论文证据关联的待验证问题（也可以诚实地输出「暂无」），说明为何值得/不值得进一步投入，最小验证先做什么、还欠缺哪类文献。
5. 收尾询问：回到第四站精读、继续一轮对话式科研思考，或结束泛读。不可替读者跳站。

**例子（非任何特定论文的实验事实）**：模型处理测试批次时依赖类别均衡。可提出「当只剩两类时，性能下降是由类别先验还是伪标签噪声导致？」下一步分别控制两个变量，并将两种解释的预期结果写清。不要直接把答案写成「引入某个 Adapter」或宣布创新。

## 精读后科研思考：第七站完成后，读者选择启动

**目标**：从主张、数据、模型、实验形成可审查的论证，明确最佳证据和真正未知，最后产出严谨的研究问题候选。

核心链路：

| 对象 | 必答问题 | 严谨性要求 |
| --- | --- | --- |
| Claim | 作者最重要的研究主张是哪一句？ | 不能偷换成插件自己的主张 |
| Evidence | 对应哪个 Figure/Table、数据集、对照和指标？ | 不能只引 Abstract 的宣传性结论 |
| Alternative | 简单基线、预训练数据、参数量、训练预算或评测选择是否同样能解释提升？ | 没有实验时只是待验证解释 |
| Falsifier | 哪一个实验结果会让核心机制解释站不住脚？ | 尽量能控制变量并具有可执行性 |
| Next experiment | 最低成本先做哪组对照？结果 A/B 分别意味着什么？ | 记录数据、指标、强基线和必要预算 |

必须覆盖 Strength/Weakness → **何时强/弱、为什么强/弱**；无对应实验的「为什么」明确为猜想，不以相关性冒充机制因果。优先使用在论文已展示原图中的全局及不利证据。不能为了凑齐优缺点各三条编造。

## 找问题的五条途径（只在有证据时选择适用项）

- **假设挑战**：发现论文设定过于理想化或与实际部署冲突；需阐明真实频率和价值。
- **失败案例**：从报告的负面结果、错误样本、真实复现失败提出可定位的机制问题；未做实验不虚构失败数据。
- **有效性反推**：当方法有效但因果机制不清楚，提出能隔离变量的反向工程式实验，而非新加一堆模块。
- **文献矛盾**：两篇**已查阅**且设置可比的论文结论冲突；先审查任务、数据、预训练、指标和预算，而不是直接断定矛盾存在。
- **真实应用倒推**：数据来源、模态缺失、实时延迟、标签权限等部署约束与 benchmark 设置不符；仍须证明这一约束重要且未被解决。

## 「研究问题候选卡」：仅当用户请求形成研究线索或第七站选择科研思考后输出

字段（宁缺勿编）：

- **问题**：具体场景 + 受影响对象 + 可测量的失败/差距 + 重要性；忌「增强模型泛化」这类大而空陈述。
- **证据**：论文原文 Figure/Table/正文、已有实验或可核实的外部文献。指出证据不足处。
- **研究假设**：可能的失效机制，与可证伪的预测；区分观察与解释。
- **简单替代方案**：不用新技术能否解决？若可以，这个问题或机制可能不值得做。
- **最小实验**：同一骨干、数据权限、预算下的一个干净对照，正反结果分别意味着什么。
- **研究风险**：问题可能只在合成设置存在、已被前人解决、改善太小、不好测量或成本过高。
- **状态**：`待核实` / `证据不足` / `值得深入调研`；**不能使用「已证创新」**，除非独立查重与验证完成，并注明范围与日期。
- **阅读下一步**：最需要查的前作/对照/benchmark，不编造文献名称。

**下游衔接**：研究问题通过初筛后，建议另行执行深入的文献查重、问题必要性审计和实验可行性审计；论文带读本身不应在单篇证据下断言“发现了顶会级新 Idea”。

## 论文汇报/知识积累（用户点选时输出，不作为每站固定长段落）

**90 秒 / 5 分钟泛读口头汇报**：三句话先讲 Problem、Method、Evidence；再用一个原图读图点与一个当前未知收尾；体现作者工作最重要的贡献，避免逐条朗读论文摘要。5 分钟版可加一条完整样本路径与一点独立问题。

**15 分钟精读组会**：研究问题与前作 → 方法运行和关键公式 → 数据及测试协议 → 主结果和关键消融 → 有证据的强/弱边界 → 自己最想讨论的一项机制假设及验证计划。明确哪些图为论文原图、哪些为辅助解释。

**研究阅读卡片**：只保留可复用要点——论文身份、Problem、关键假设、方法一句话、主要结果及条件、支持证据编号、关键风险、学到的科研技能、自己的一个开放问题、下一步检索/复现实验。禁止凭空生成具体数字、真实文献引用；用户未要求导出文件时直接给紧凑文本。

**沟通与反馈**：学生提出尚不成熟的问题时先定位其值得检查的前提，不无依据称赞「很有创新」，也不否定提问；多用「你的假设需要哪张图或哪组实验才能检验？」。讨论结束留下一个明确的小行动，避免有问题却只做口头总结。

## 判断何时继续精读

泛读结束时，基于论文与用户研究目的，简要判断**精读价值**：它是否研究重要问题？方法是否有值得复现的新机制？数据/实验协议是否值得学习？与读者关注领域相关吗？给出「建议完整精读」「建议选择性精读」「泛读即可」之一，需说明理由、区分现有证据和待核实之处。**不是对论文质量作最终评价，也不强行阻止读者进入下一站。**
